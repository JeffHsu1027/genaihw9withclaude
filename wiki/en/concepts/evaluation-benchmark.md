## One-line definition

A fixed set of tasks plus a scoring method, used to measure an ability or the quality of an output in a repeatable way.

## Explanation

Designing an evaluation means answering three questions: what is being evaluated, where the ground truth comes from, and how the score is computed.

Ground truth comes from roughly three places. The first is computation by a program, which is exact and scales well but only suits questions with a clear right answer. The second is human annotation, which can handle more subjective judgments but is costly. The third is another model acting as judge, which scales but requires separate validation of the judge's own reliability.

A good evaluation must also avoid a common problem: if the system under test saw the evaluation content during training or development, the score no longer means what it should.

## What each source says

### LLM Game Rule Understanding through Out-of-Distribution Fine-Tuning (2025)

[This paper](../sources/2025-llm-game-rule-understanding.md) evaluates **a model's ability**: whether an LLM understands game rules.

- **Task**: given a Solitaire state and an action, decide whether it is legal and output the next state (p.2).
- **Ground truth**: computed automatically by the simulation framework. Because rules are defined in a [game description language](game-description-language.md), the framework can validate any action and execute it to get the next state (p.7).
- **Score**: legal accuracy and next-state accuracy (p.8).
- **Scale**: 6 test variants with 500 questions each (p.7).
- **Distinctive feature**: test sets are split by their relation to the training set into in-distribution, in-family, and out-of-distribution, to measure [generalization](out-of-distribution-generalization.md) (p.7).

### GUI Agents for Continual Game Generation (2026)

[This paper](../sources/2026-gui-agents-continual-game-generation.md) evaluates **the quality of an output**: whether a generated game behaves as intended. It builds PlaytestArena.

- **Task**: 200 web game generation prompts across 8 genres (p.4).
- **Ground truth**: there is no single correct answer. Instead, human experts write rubrics, 1,548 observable expected behaviors in total (p.4).
- **Score**: a GPT-5.5 [GUI agent](gui-agent.md) plays the game and judges each criterion; the score is the fraction passed (p.4).
- **Validating the judge**: agreement with human annotation is 87.9% (κ = 0.66), close to the 91.4% (κ = 0.68) between humans. With two other models as judges, the ordering of methods stays the same (p.4–5).
- **Avoiding leakage**: the playtester inside the generation loop never sees the rubric and does not produce the final score (p.5).

### Comparing the sources

| | 2025 rule understanding | 2026 PlaytestArena |
|---|---|---|
| What is evaluated | A model's ability | Generated games |
| Ground truth | Computed by a simulator | Human-written criteria |
| How it is judged | Compared with the ground truth | Judged by an agent after playing |
| Where questions come from | Generated by a program | Written by human experts |

The first has questions with clear right answers and can be fully automated. In the second, quality is only known after playing, so it needs a judge that can play, and the judge's reliability has to be validated as well. Neither paper cites the other; this comparison is this wiki's own synthesis.
