一句話總結

作者主張遊戲生成需要一個「玩家」，讓 GUI 代理人實際去玩生成出來的網頁遊戲：既用它建立評測基準 PlaytestArena，也把它放進生成流程成為 Play2Code，使平均準則通過率達到 66.8%，高於單次生成的 29.7% 與不試玩的代理式流程的 52.2%。

研究問題

生成一個遊戲不等於做出一個能玩的遊戲。遊戲可以編譯、執行、通過所有測試，卻仍然有靜態分析看不出來的問題，例如按鍵沒有反應、圖像沒有顯示、勝利條件永遠不會觸發。遊戲產業因此長期依賴人類測試員，但 LLM 產生遊戲的速度已經超過人類能試玩的速度（p.1）。

論文提出三個問題（p.2）：

  1. 遊戲的本質如何改變「更好」的定義？
  2. 「玩家」應該長什麼樣子、放在流程的哪裡？
  3. 這樣的「玩家」如何推動遊戲生成，方向是否與人類一致？

方法

先確認 GUI 代理人能不能試玩。 作者用 20 個網頁遊戲（拆成約 120 個關卡）測試三個模型，並請三位人類玩家在相同條件下遊玩作為對照（p.3）。

PlaytestArena：評測基準。 包含 200 個網頁遊戲生成任務，涵蓋 8 種類型，遊戲以獨立的 HTML/CSS/JS 檔案呈現（p.4）。每個任務有兩部分：

  • 由人類專家撰寫的生成提示，平均 131 個 token，說明玩法、勝負條件、玩家輸入與回饋行為。
  • 由人類專家撰寫的評分準則（rubric），每一條描述一個可觀察的預期行為，例如「生成的敵人會朝玩家的位置移動」。全部共 1,548 條，每個遊戲 5 到 17 條、平均 7.7 條，分屬機制、操控、進程、介面與視覺回饋五個面向（p.4、p.14）。

評分由獨立的 GPT-5.5 GUI 評審執行：它在瀏覽器載入遊戲，用點擊與按鍵遊玩，再依觀察到的過程對每條準則判定通過或不通過。分數是通過準則的比例（p.4）。

Play2Code：把試玩放進生成流程。 兩個代理人圍繞同一個執行環境合作（p.5）：

  • 遊戲代理人（Game Agent）負責撰寫、除錯與修改程式碼。
  • GUI 測試員在瀏覽器遊玩目前的版本，看不到程式碼，也看不到評分準則。結束後產出兩份文件：遊玩摘要，以及把觀察到的問題對應到程式修改方向的修正清單（p.5–6）。

遊戲代理人把這份報告當作建議而非指令，自行決定採納哪些修正。流程在測試員判斷遊戲已符合提示的意圖，或達到回合上限時結束（p.6）。回合上限為 5，平均實際執行 3.24 回合，93.5% 的任務提前結束（p.18）。

三層記憶。 依生命週期（任務內或跨任務）與範圍劃分為情節記憶、技能記憶與世界記憶，讓經驗能在回合之間與任務之間累積（p.6）。詳見代理人記憶。

比較對象。 Direct LLM 一次輸出整個遊戲；OpenGame 是代理式流程，會反覆建置、執行並在語法與編譯層次檢查，但不試玩。三種方法都分別以 GPT-5.4、Claude Sonnet 4.6、Kimi K2.5 作為骨幹模型（p.6）。

主要結果

GUI 代理人能夠試玩，但仍不及人類。 20 次嘗試內的關卡通過率：GPT-5.4 為 0.82、Sonnet 4.6 為 0.79、Kimi K2.5 為 0.72，人類為 0.92（Table 1，p.3）。

試玩帶來明顯提升。 各方法在 PlaytestArena 的平均準則通過率（%）（Table 3，p.6）：

骨幹模型 Direct LLM OpenGame Play2Code
GPT-5.4 31.6 55.7 72.3
Sonnet 4.6 29.7 55.3 71.1
Kimi K2.5 27.8 45.5 56.9
三者平均 29.7 52.2 66.8
  • 與 OpenGame 的比較最能說明問題：它已經會反覆建置與檢查，只差沒有試玩。操控沒反應、缺少狀態轉換、勝利條件不觸發這類問題，在程式碼與編譯層次看不到，只有遊玩時才會浮現（p.6）。
  • 分數隨回合單調上升。早期回合多半暴露基本的互動問題，後期回合處理較細的問題，例如視覺效果（p.7）。

消融實驗（以 GPT-5.4 為骨幹，p.18–19）：

設定 準則通過率
完整 Play2Code 72.3
完全不用記憶 64.1
移除 GUI 測試員，改由遊戲代理人自我檢查 58.7

移除 GUI 測試員造成的下降比移除任何一層記憶都大，作者據此認為實際遊玩的回饋是影響最大的元件（p.19）。

評審可靠嗎。 GPT-5.5 評審與人類在準則層次的一致率為 87.9%（κ = 0.66），人類彼此之間為 91.4%（κ = 0.68）。改用 Claude Opus 4.8 與 Gemini 3.5 Flash 當評審，三種方法的排序不變（p.4–5）。

與人類測試員的比較。

  • GUI 代理人的每個動作、觀察與診斷都有紀錄，問題可以回溯到具體的畫面序列；人類的報告則是事後的摘要（p.7）。
  • 在 50 個中等增益的遊戲上，GUI 代理人推動改進的效果接近人類測試員（p.7）。
  • 不同模型關注的重點不同：GPT-5.4 集中在功能錯誤與操控反應，Sonnet 4.6 較平均並關注節奏與難度平衡，Kimi K2.5 有將近一半的回饋關於視覺與美感（p.7–8）。

成本。 每個遊戲的平均推論成本約為 Direct LLM 5 美元、OpenGame 12 美元、Play2Code 17 美元（Table 8，p.18）。

限制與未解問題

  • 只處理 HTML 網頁遊戲，尚未延伸到原生引擎或 3D 遊戲（p.9）。
  • 基準是為了品質控管而精選的一組遊戲，無法涵蓋真實世界遊戲的多樣性（p.9）。
  • 所有遊戲共用同一套記憶結構，依遊戲或類型設計的記憶結構可能更好（p.9）。
  • 作者承認人類測試員仍無可取代：對難度、挫折、無聊與驚喜的實際感受，以及美感判斷，目前沒有代理人能近似（p.7）。
  • 遊戲依「實際獲得的改進幅度」分組，作者提醒這不代表遊戲本身的難度，也不能推論複雜度決定改進幅度（p.7）。
  • Play2Code 的成本高於兩個比較對象（p.18）。

與其他來源的關係

  • LLM Game Rule Understanding through Out-of-Distribution Fine-Tuning（2025）：兩篇都在建立與遊戲有關的評測方法，但評測的對象不同。那一篇評測的是模型，問 LLM 能否依文字規則推演盤面，標準答案由模擬器算出；這一篇評測的是生成出來的遊戲，由代理人實際遊玩後依人類撰寫的準則判定。兩篇的動機也相近，都希望 AI 能在遊戲開發中提供回饋。這一篇沒有引用那一篇，以上是本 Wiki 的整理。
